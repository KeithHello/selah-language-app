# Selah 循环听整体开发计划

> 面向后续执行者：取得循环听代码实施授权后，使用 `executing-plans` 技能逐任务执行与验收。所有复选框代表未来工作，本计划不触发自动实施、agent 分派、付费调用或部署。

**目标：** 在正式 Web「聆听」内提供完整句库的逐句双语循环、双向语序、15／30／60 分钟与自定义停止时间，以及跨页和经真机验证的后台播放。

**架构：** 纯 Dart 模型建立队列与配置，`LearningController` 协调账户、资源和偏好；浏览器音频层拥有唯一运行会话与截止时间。页面和迷你播放器只读取同一状态；循环音轨结束不进入学习完成记账。

**技术栈：** 现有 Flutter Web／Dart、`dart:js_interop`、HTML 音频元素、Cache API、IndexedDB、Supabase 和 `tts-1`／MP3；不新增 Flutter 或全局依赖。

**设计依据：** [UI／UX 设计](../specs/2026-09-10-loop-listening-design.md) 、[静态界面总览](../specs/2026-09-10-loop-listening-ui.png) 、[项目规范](../../../CLAUDE.md) 。

**当前状态：** 2026-09-10 仅完成设计与开发分解，尚未创建本计划列出的产品文件、测试或音频。测试命令与预期均为未来验收方案，不是已执行记录。

## 1．全局约束

- 仅正式 Web 入口，保持旧原生 Flutter 与 Swift 客户端的工程边界。
- 本轮只交付文档与静态稿，不改产品代码、测试、应用资源、配置或构建产物。
- 完整句库＝当前账户已收录、未归档的全部句子；不自动加入种子目录中未收录的内容。
- 默认学习语言后母语；每句语种间隔 1 秒、句间间隔 2 秒，间隔不随语速缩放。
- 默认 30 分钟，预设 15／30／60 分钟，自定义 1～720 分钟整数。
- 从首段真实发声开始计时；暂停、缓冲和错误不延后截止；到期中断当前音轨且不再开启下一段。
- 循环播放独立于学习完成、熟练度、复习状态与成长奖励；不新增云端循环统计。
- 复用现有模型、声线、MP3 与缓存；不静默回退浏览器朗读、假音频或 Mock 成功。
- 单页只有一个发声源，账户切换使旧会话及其异步结果失效。
- 数据库、依赖、密钥、配置、CI、真实付费调用、远端操作和公开发布保留原有独立确认边界。
- 本功能的预算不沿用旧功能的付费验收授权；批量母语音频预制另行列出数量与成本再确认。
- UI／UX 设计文档的 R01—R16 和 S01—S06 为本计划的验收合约，未通过验证的事项不得勾选。

### 3.1 共享类型合约

| 类型／字段 | 约定 |
| --- | --- |
| `LoopOrder` | `targetFirst`、`sourceFirst` |
| `LoopOptions` | `order`、`durationMinutes`；默认 `targetFirst`／30；范围 1～720 |
| `LoopAudioTrack` | `role`＝`target` 或 `source`；`language`、`cacheKey`、`textHash`；只携带真实准备好的音轨引用 |
| `LoopQueueItem` | `sentenceId`、本轮文本版本、双语显示文本、`targetTrack`、`sourceTrack`；每个 ID 一次 |
| `LoopSessionSnapshot` | `sessionId`、`status`、`order`、`pendingOrder`、`sentenceIndex`、`sentenceCount`、`phase`、`positionMs`、`startedAtMs`、`deadlineAtMs`、`remainingMs`、`stopReason`、安全错误码 |
| `status` | `idle`、`preparing`、`ready`、`starting`、`playing`、`gap`、`paused`、`ended`、`error` |
| `phase` | `target`、`source`、`betweenLanguages`、`betweenSentences`；无运行音轨时可为空 |
| `stopReason` | `timeout`、`user`、`accountChanged`、`emptyQueue`、`voiceChanged`、`disposed`；暂停不等于结束 |

`preparing`／`ready` 是控制器资源准备状态；从 `starting` 到运行终态由浏览器会话提供唯一权威状态。Dart 仅解析运行快照，不能另有一套会推进音轨的倒计时逻辑。会话 ID 和账户世代用于屏蔽旧回调，剩余时间是由截止时刻计算的读数。

### 3.2 控制器与桥接边界

| 拟定入口 | 输入／输出及行为 |
| --- | --- |
| `prepareLoop()` | 使用当前账户未归档句子和当前声线；准备完整双语音轨；产出准备进度或 `ready`，不启动播放 |
| `startLoop()` | 仅在 ready 且用户主动点击时调用；冻结本轮队列、声线与时长，创建新 sessionId |
| `pauseLoop()`／`resumeLoop()` | 使用同一会话；暂停不改截止；恢复前检查到期和其他媒体占用 |
| `nextLoopSentence()` | 跳过当前句剩余音轨，进入下一句的首种语言，不重置计时 |
| `setLoopOrder(order)` | 无会话时更新设置；运行时保存下一句生效的 pendingOrder |
| `stopLoop(reason)` | 释放本会话资源及异步准备，保留已成功缓存，不修改学习记录 |
| `audioLoopStart` | 桥接 action；输入账户、sessionId、双语音轨队列、order、durationMs、speed；首段真实 playing 后确定截止 |
| `audioLoopStatus` | 返回 `LoopSessionSnapshot` 的运行字段；UI 轮询仅显示状态 |
| `audioLoopPause`、`audioLoopResume`、`audioLoopNext`、`audioLoopStop`、`audioLoopOrder` | 带 sessionId；旧会话操作安全失效；统一走媒体资源拥有者 |
| `audioLoopUpdateQueue` | 当前账户有效的新队列版本；归档过滤在音轨边界生效，其余变化在下一轮生效；缺音轨时不静默遗漏 |

现有 `LearningPlatform.invoke` 已能承载 JSON action，不为这些方法另加 SDK 或公共网络协议。Dart 与 JS 的字段名在各自测试中逐项对照。
