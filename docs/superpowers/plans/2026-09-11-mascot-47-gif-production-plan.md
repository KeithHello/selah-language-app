**Tech Stack:** 项目现有 Python、Pillow；现有 NumPy／SciPy 仅用于已有图像检查，不安装新依赖。HTML／CSS／原生 JavaScript 只用于独立审阅。

## 全局限制

- 恰好 47 个新动作：S1 的 A04—A10、S2—S5 的 A01—A10。
- 一动作一 GIF，不生成五个阶段合辑来代替独立动作。
- 每项 768×768、16 帧，4×4 图集为 3072×3072。
- 透明背景、无地面影子、无额外角色／道具／文字，任意可见像素距边至少 93 px。
- 固定身体、五官、材质和同阶段植物结构，不跨阶段借图，不独立扭动花叶，不重绘躯干。
- 每阶段共同尺度，只允许一次记录在案的来源位置校准；禁止单帧缩放或坐姿放大。
- 同阶段共享调色板；每帧显式 duration、`disposal=2`，GIF `loop=0`。
- 新动作首尾同源同变换。读取实际编码帧数，不能用逻辑帧数代替解码结果。
- 原始 PNG、已有三个参考 GIF、其余历史输出与应用资源均不覆盖。
- 本计划不包括应用接入、数据库、配置、安装依赖或部署。
- 预览循环不等于业务循环，产品触发规则以每项 `futureProductPlayback` 为后续参考，另行接入。

## Task 2：清理与配对预检

**输入：** 锁定源图、`sourceIds`、`reviewFocus`、全部逐帧变换。

**产出：** 五阶段准备图、静态配对对照、记录相容性的 `preflight.json`。

- [ ] 目视确认原图底部投影，再对工作副本使用已有窄范围清理规则；只移除低 alpha 中性地面投影，保留脚掌和身体明暗。
- [ ] 在白、深灰、棋盘格底色分别核对脚底和边缘。连通分量、四角透明只能辅助检查，不能代替视觉判断。
- [ ] 对每项候选来源，在同一画布并排和叠加比较眼线、腹部中心、身体宽高、花叶根部及落脚高度。
- [ ] 只为明确的原图画布偏移做一次平移校准并记录。不同姿态真实的坐高、抬脚高度和身体倾斜不拉平。
- [ ] 如果体型、颜色或植物结构不相容，撤去对应辅助姿态，使用该项记录的退路并标记需复核；不得通过每帧缩放或局部擦改身体掩盖。
- [ ] 以该阶段所有变换后的可见并集计算共同尺度和位置，确保 PNG 任意 alpha＞0 像素保留至少 93 px 边距；必要时降低整阶段共用尺度或该动作幅度。
- [ ] 固定每阶段调色板和布置。记录调色板只能稳定量化，不能被当作原始色差已修复的证据。

**通过条件：** 使用到的每一对源姿态经过静态审阅；五阶段均记录固定布置；无已知影子、裁切或源身份不相容问题进入下一步。
