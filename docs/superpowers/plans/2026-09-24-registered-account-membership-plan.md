# 正式账户、会员权益与请求限流实施计划

> 状态：主人已授权在当前工作区实施。此文是本地开发记录，不代表任何远端 migration、认证配置、支付配置或部署已执行。

## 目标

取消匿名云端测试路径，改为未登录访客本机使用、正式注册账户使用云端功能。服务端分别识别试用、Plus 与 Pro 权益，并避免分段批量处理因逐句频控而中途失败。

## 产品规则

- 未登录访客可使用随包示例、本机学习、本机循环听和本机备份；云端生成、长文整理、转写、个人音频、同步及会员资料要求正式登录。
- 旧匿名会话在启动时本机退出。保留 `guest` 本机命名空间，账户登录后由用户选择导入；不自动合并或删除旧匿名云端资料。
- 所有 Edge Function 认证入口拒绝 `is_anonymous=true`。新 migration 为现有 `authenticated` RLS 政策附加正式身份条件。
- Plus／Pro 额度由服务端账本决定。Pro 沿用 `pro-v1` 额度，可由受审计的管理员动作授予；没有真实支付渠道与验签时不开放自助购买。
- 分句仍逐条幂等和计入句子额度，批量请求本身只占一个分钟频控名额。语音转写与长文整理使用独立的分钟／日频控类别，并向客户端传递 `Retry-After`。

## 实施任务

1. **先补回归测试**：未登录生成／转写不触发匿名登录；旧匿名 JWT 被所有认证入口拒绝；批量频控按一次请求计算且逐句额度不变；Pro 会员状态、额度及管理员授予合约通过。
2. **客户端准入**：移除自动匿名登录；旧匿名会话启动时退出；未注册访客保持本机资料；云端操作返回 `login_required` 并提供登录／注册入口；三语会员与限流错误信息准确。
3. **服务端身份**：统一拒绝匿名 JWT；旧管理开关不能再授权匿名请求；本地 Supabase 配置关闭匿名登录。
4. **权益与分段限流**：新增本地 migration，扩展 Pro 会员计划、服务端额度与管理员授予；将转写、长文整理与批量请求的频控账本拆开。
5. **验收与文档**：运行相关 Flutter、Node、Deno 测试、静态分析和 Web Release 构建；更新项目规范与路线图，列明远端执行步骤与未决阻塞。

## 数据和外部操作边界

- migration 只提交为可审阅的本地草案；不应用远端数据库，也不读取、修改或清理线上用户数据。
- 远端 Supabase Anonymous Sign-ins 开关、正式邮件确认／SMTP、支付渠道及密钥、Cloudflare 配置和部署都需单独确认。
- 旧匿名云端行保留。完成远端迁移后，仍需单独盘点归属、保留期限和清理策略。

## 验收标准

- 新访客浏览器不会生成匿名 Supabase 身份；登录前的云端操作在客户端被拦下并可直接打开登录／注册。
- 旧匿名 token 即使仍有效，也不能调用认证 Edge Function 或通过 `authenticated` RLS 读写个人资料。
- Plus 与 Pro 均由服务端返回正确静态权益；Pro 可被管理员按月份授予并记审计，普通用户仍不能自助购买 Pro。
- 一批 2—20 个分句不因逐句 claim 占满分钟频控；重复请求继续幂等，日限额和会员句数按实际分句数核算。
- 转写和长文整理频控相互独立；429 错误带有 `retryAfterSeconds` 并显示可理解提示。
- 随包示例、本机保存、循环听、本机备份与登录后显式导入继续可用。
