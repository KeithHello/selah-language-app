## 1．目标与方案选择

目标是让 Web 的“输入或录音 → 英文学习材料 → 音频 → 聆听／练习 → 跨设备复习”在真实环境可用，并减少丢失输入、重复生成和无法核对的费用。

采用现有架构内分阶段改善：先修会影响内容保存和生成的行为，再完成服务上线、用量记录与真实环境验收。仅做可达性联调无法解决输入／分段问题；重写前端或引入多供应商路由会扩大范围，当前不采用。

三个文档各有职责：

- [费用调研档案](../../2026-09-07-web-ai-cost-research.md) ：保留官方价格、替代方案、测算和用户决策。
- 本文：逐项解释“原本怎么样、修改后怎么样、怎样验收”。
- [整体开发计划](../plans/2026-09-07-selah-web-improvement-plan.md) ：安排任务、文件、依赖和检查点。

固定边界：OpenAI gpt-4o-mini-transcribe、gpt-4o-mini、tts-1，现有四个 voiceProfile、MP3、Supabase Storage 和缓存继续使用。默认生成速度保持 0.85；播放速度继续由浏览器调整。保持现有品牌和五阶段五十姿态，不扩大到 iOS／旧原生 Flutter、自动发音评分或新的目标语言。

### P1：减少重复调用并明确失败状态

| 编号 | 原本怎么样 | 修改后怎么样 | 验收标准 |
| --- | --- | --- | --- |
| W04 整理与批次重试 | 每次 prepare 新建请求 ID；单句和批量子段已有稳定 ID；部分完成后需要保存各段结果与失败状态 | 对同一账户、同一输入版本保留整理请求 ID 和成功结果；修改原文生成新 ID；每段绑定稳定 ID，重试仅发送未完成段 | 上游成功但回包超时后使用原 ID 重放；编辑后不误用旧结果；跨页和刷新后恢复批次；已完成段不重复收费 |
| W05 已生成文本复用 | 成功后草稿被移除；再次提交相同中文通常会新建生成请求 | 对当前账户、相同文字和可确认的生成版本复用已保存句子；保留显式重新生成入口；复用保留原复习与词汇状态 | 命中时模型调用数为 0、学习事件不重复；版本不明的旧句仅提示打开历史结果；用户选择重新生成才创建新请求 |
| W06 输出合约与长度 | 单句使用 JSON Object，批量使用 JSON Schema；词汇提示同时出现“2—4”和“最多 3”；输出 token 未明确设上限，部分字段仅做宽松校验 | 统一教学输出验证和词汇规则；限制输出长度；截断、缺项与无效字段作为明确失败保留草稿，避免空字段冒充成功 | 词汇 0—3 项，英文非空且不超过 1000 字符，类别在现有六类中；单句和批量同样校验；长度终止、重复段 ID、缺段均有测试 |
| W07 真实用量与费用可核对 | usage_records 主要记录 estimated_units=1；转写与整理共用 capture_preparation 额度；请求失败与厂商是否收费没有完整对应记录 | 保留原额度保护，新增供应商调用尝试级的用量观察，区分功能、模型、缓存、失败和费用未知；按版本化价格估算并与账单对照 | 单次供应商调用只记一次；五句合并请求不把 token 算五遍；账本重放不记新调用；缺失 usage 标为未知；不记录原始文字、音频或凭据 |
| W08 音频失败恢复 | ready 音频可复用；queued／generating 只看状态就一直复用；上游成功但上传或清单更新失败存在再次合成或长期等待路径 | 给进行中状态增加过期判定和原子认领；重试前先确认已有 Storage 文件；能修复清单／签名链接时只修复交付；在当前请求内有限重试上传 | 并发同内容只启动一个生成者；过期任务可恢复；已存在有效 MP3 时 OpenAI 调用数为 0；签名失败和缓存丢失不重新合成 |
| W09 默认种子离线覆盖 | 包内 11 段音频，仅 8 条默认声线种子；其余依赖网络获取 | 取回并校验已存在的默认声线 30 条，纳入离线资源；另外三种声线按需下载，已有的内置音频保留 | 默认 30 条逐项 ID、字节数和 SHA-256 一致；完成资源缓存后离线可播；缺文件单独报告，不用 TTS 重新补生成 |

W04 不把批量顶层请求的新 ID 等同于子段幂等失效；现有服务端按 segmentId 认领，继续保留这一机制。恢复逻辑以实际保存状态为准，不凭前端“请求发送成功”判断厂商执行状态。

W05 使用保守规范化：去掉两端空白、统一换行，保留大小写和语义标点。不进行跨用户私人内容共享，不把近似语义视为同一请求。旧数据若缺少模型／提示词版本，不伪造版本用于自动命中。

W06 初始输出预算建议为：单句 2048、整理 4096、批量 8192 个输出 token，实施时先验证 500 字输入、20 段整理和 5 段批量的最长合法样本。若预算导致完整合法内容被截断，调大预算并记录理由；不得裁剪 JSON 字符串制造成功。词汇规则统一最多 3 项；拆解沿用现有客户端 50 项安全上限并要求短释义，先避免新增任意的教学内容裁切。

W07 将“供应商报告的实际单位”和“按官方价格计算的估算费用”分开：客户端 durationMs 属于声明值，不能冒充服务器测得时长；未知用量不能写 0。涉及数据库表／RPC 的变更需要独立确认。第一阶段不放宽现有请求额度，也不同时扩大转写与整理的总额度；分拆配额及金额硬上限在有真实用量后另行审阅。

W08 不能承诺上游响应丢失且未持久化音频时仍可保证零重复收费。该状态必须标为结果未知，限制自动重试，避免把全链路误称为严格 exactly-once。

## 4．数据与交互约定

### 4.1 本机输入与分段状态

复用当前账户的 LearningSnapshot 存储。计划增加可选的 preparationDraft，保存请求 ID、输入原文及版本、语言、成功整理结果与编辑后的分段。每段包含稳定的段 ID、顺序、文字和 pending／succeeded／failed 状态；进行中标记刷新后恢复为可重试，不能永久锁住。

旧版没有该字段时按空草稿读取；现有 version=1 备份兼容继续保留。输入和中间分段保留在本机，不进入云端业务表。既有 segmentInputs 的 take(5) 同步调整为完整、有上限的校验；超过支持数量明确报错，不静默截取。

前端始终先存本机请求状态，再发送网络请求；完成后先保存成果，再清理对应草稿。保存失败显示失败且保留可恢复内容。

### 4.2 单次生成与重试身份

- 未改动输入的传输重试使用同一个 clientRequestId。
- 用户改动输入或明确要求新结果时，使用新的 ID。
- 批量请求继续传 segmentId；服务器只生成尚未完成的段。
- 请求结果到达时校验账户和草稿版本，不覆盖新的输入或其他账户状态。
- 重复点击、网络超时和本机写入失败分别验证；不以无限重试隐藏错误。

### 4.3 用量记录边界

建议以 attemptId 标识实际供应商请求，并关联稳定业务请求 ID。记录 model、feature、供应商 request ID、输入／输出／缓存 token、合成字符、时长来源、结果状态、价格版本与 estimatedCostUsd。

batch 的 token usage 属于一次供应商调用，不能完整复制给每个段再求和。用于产品统计的按段分摊必须明确标记为分摊。用量元数据采用字段白名单，与学习事件自由文本隔离。
