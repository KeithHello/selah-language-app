## 2．实施方向

推荐扩展现有 Dashboard，复用账户、数据和成本统计。只增加一个可任意切换的「是否会员」开关无法解释期限、付款来源和重复赠送；另建独立管理系统则会增加登录、权限和部署维护。当前规模采用现有后台加明确的会员操作即可。

本方案把「普通用户」理解为没有有效月会员的注册用户，「正常会员」统一称为「月会员」，不再新增一个容易混淆的会员档位。

用户身份由服务端权益时间线推导：普通用户、试用中、试用结束、月会员有效、月会员到期。会员来源另标付费、赠送或补偿；新增生成被暂停是独立服务状态，不冒充会员到期。管理员可以查看权益明细，用户端依旧只显示身份、有效期和静态方案说明。

## 3．会员操作规则

| 后台操作 | 处理规则 |
|---|---|
| 补发已购会员 | 选择已存在的订单，服务端重新核验到账并恢复该订单缺失的权益；同一订单已有权益时返回原结果，不再送一份，不把恢复时间当新的购买时间 |
| 登记已核实收款 | 对平台外已经实际收款的订单，由具备财务管理权限的人填写收款渠道、交易编号、金额、收款时间、购买月数、凭证引用与原因；标为「人工核实」，与渠道自动核验分开统计；首版仅支持已批准渠道的原价整月购买 |
| 赠送会员 | 提供 1／3／6 个月快捷项及 1—12 个整月输入；没有有效月会员时立即开始，已有会员时默认排到已确认权益结束后；保存前展示全部起止日期与预算影响 |
| 客服补偿 | 沿用赠送流程，来源标为补偿并关联故障／客服记录；首版用整月补偿，不开放任意清零用量或无限加量 |
| 撤销误赠 | 选择具体赠送记录，撤销其尚未使用的部分；已发生费用、历史记录与在途请求继续保留和结算，不撤销真实支付订单 |
| 暂停／恢复新增生成 | 处理明确的异常使用，仅影响新的 AI 调用；记录原因与操作者。恢复时沿用原账期、已用额度与费用账，不重置预算；已有内容继续可学习 |

### 3.1 开通、续期与按月权益

赠送会员享有与同版月会员一致的四项权益及成本保护。赠送 3 个月表示 3 个独立月账期，每期 300 条表达、30000 配音字符、60 分钟转写、30 次整理，不在第一天发放 3 倍额度。月份与月末锚点沿用主设计，UTC 存储、界面显示明确时区。

普通用户在 9 月 11 日 10:00 获赠 3 个月时，三个账期依次在 10 月 11 日、11 月 11 日、12 月 11 日 10:00 结束。有会员到 10 月 10 日的用户获赠 1 个月，则延续到 11 月 10 日，当前账期用量不变。以上均为示例日期。

新赠送的开始时间取服务端当前时间与已确认会员权益时间线末端中的较晚值。若存在撤销造成的空档，确认页显式展示空档，不悄悄移动之后已确认的付费期间。试用转为立即生效的赠送会员，按主设计的转会员规则终止试用资格，旧试用在途请求仍结算原记录；撤销赠送不重新赠送试用。

赠送会员有效期间购买月会员，与现有会员续购一致排队顺延；付款前说明实际开始日期。付款回调、人工补发、人工收款与赠送共用同一账户时间线锁和交易唯一约束。补发历史订单若与后续记录冲突，进入人工核对并展示冲突，禁止覆盖现有期间、重复扣款或再次发放相同权益。

人工收款记录不伪装成支付渠道已验签结果。相同渠道／交易编号只能关联一个订单；后续渠道回调与人工记录匹配到同一订单时，仅补充核验来源，不重复发权益。未能核实收款时不能记成已支付；如需临时帮助用户，可以明确使用赠送并按赠送预算记账。

### 3.2 赠送必须计入成本

赠送收入为零，模型费用与付费会员相同。后台确认页显示赠送月数、每月权益、有效期、内部模型预算承诺和赠送预算池影响。假设每月 20 元的目标最终验证通过，赠送 3 个月需要预留 60 元模型预算容量；这个数字仍不包含基础设施，也不是当前已经生效的保证。

创建赠送时，事务检查并登记整段未来权益的预算承诺，同时检查赠送预算池和平台可承诺容量；任一不足或未配置时不发放。每期开始后分配该期个人预算，每次调用仍经过主设计的权益与费用预占。未来容量承诺和已发生 API 费用分别统计，实际消耗转换对应占用，不重复计算两次。撤销只释放可以证明尚未使用的承诺，未知计费和在途预占不能清零。

该机制同样用于付费、补发和补偿；已有订单已预留的容量必须复用。后台没有「管理员不受限」「无限会员」或「强制通过预算」按钮。活动赠送与服务补偿分来源汇总；不因为赠送人数增加而突破平台总承诺容量。

### 3.3 权限、确认与审计

首版只分「查看后台」与「管理后台」两类能力；拥有查看权限不自动获得赠送、收款登记、暂停或预算修改权限。沿用 `admin_members` 识别后台人员，再由服务端明确核验写权限；没有配置时默认只读，首次管理权限由主人通过项目的授权流程指定。授予产品月会员不会授予管理员权限。

每次写操作必须保存操作者、目标用户、动作、原因、原状态、新状态、关联订单／赠送／客服记录、预算变化、服务器时间和请求 ID。只追加审计事件，修正通过关联的反向操作记录完成，不删除历史。用户列表展示脱敏邮箱，查询和确认以唯一用户 ID 为准；不读取用户原始句子、录音或密码来办理会员。

流程为「选择用户→选择动作并填原因→服务端预览日期及成本→确认提交→显示生效结果与审计编号」。预览返回权益版本，提交时重新检查权限、版本、额度与容量；版本变化要求重新预览。相同操作 ID 和相同负载返回原结果，不同负载拒绝；失败不得留下只有会员或只有预算的一半结果。

撤销赠送、暂停生成和修改预算需明确展示影响并二次确认。预算调整必须有生效时间和版本，不低于已结算、在途和已承诺责任；提高预算不能绕过主设计的收费上界证明。已有交易／权益不允许从表格中直接编辑状态或日期。

## 5．用户详情与操作面板展示

用户列表列项：用户标识、脱敏邮箱、会员状态、来源、有效至、生成服务状态、最近活跃、操作。点开用户后，主区域为会员时间线与订单；「内部用量与费用」作为管理员专用区展开查看。

赠送面板示例：

```text
赠送月会员
用户：已选定的用户 ID 与脱敏邮箱
赠送时长：［1 个月］［3 个月］［6 个月］［自定义］
生效方式：到现有会员结束后顺延
生效期间：服务端预览的起止时间与时区
每期权益：300 条表达／30000 配音字符／60 分钟转写／30 次整理
当期影响：现有已用额度不重置
费用影响：内部预算承诺与赠送池变化
赠送原因：必填
［取消］                       ［确认赠送］
```

正常成功提示为「已赠送 3 个月，会员有效至……」；重复提交提示「本次赠送已处理」并展示原结果；预算不足提示「赠送预算不足，未修改用户权益」；状态变化提示「该用户的会员记录已更新，请重新确认」。提示准确反映事务结果，避免先改页面后等服务器失败。

用户端只显示「月会员」「赠送／补偿来源」和有效期，下一账期已排队时可查看其日期；不显示内部预算或剩余额度，也不强行跳转促销弹窗。自动邮件、短信或站外消息不属于首版。

新增后台支持现有繁体、简体、日语文案；继承当前统一 `nativeLanguage` 派生界面语言的实现，不另加语言偏好。宽屏表格与窄屏详情可访问，操作有可见标签、键盘焦点和提交状态；不只用颜色区分付费、赠送和暂停。

后续增加可收藏的同源 `/#/admin` 入口，内部子页为 `/#/admin/users` 等受控路径；这只是计划地址，目前不可作为已可用入口。只用既有 Flutter／浏览器能力，不新建站点或改变部署方式。未登录时完成登录再返回后台，非管理员被拒绝；刷新、后退、会话过期和角色撤销必须重新核验，URL 本身不授予权限。

## 6．接口与数据实施边界

复用主计划 T02 的订单、账期、权益及预算账；为权益补充来源、关联订单／赠送、操作者和撤销事件，为未来赠送建立容量承诺。不能只给用户表新增 `is_member` 字段后让客户端据此调用模型。

保留 `admin-summary` 的只读职责，最终方案统一为受控总览／用量／订单／日志视图；新增 `admin-users` 查询列表与详情、`admin-membership-actions` 处理上述预览和提交、`admin-service-controls` 处理平台应用内准入开关与预算版本。共用主计划的账期与预占服务。查询接口使用最大 100 条的有界页大小和服务器游标，会员与成本筛选分别验证，普通用户不能查询其他账户。

最终整合时发现现有统计调用尚未显式传递 `p_admin_user_id`，而 SQL 会据该参数或 `auth.uid()` 核验管理员。T08a 已列入参数断言、服务端已验证身份传递与真实数据库回归；本轮只记录源码缺项，没有修改代码，也未将其推断成已验证的远端故障。

动作请求只接受受控动作、目标用户、整月数、订单／赠送引用、原因、请求 ID 与预览版本；操作者由已验证登录身份取得，金额由已批准 SKU 及核实收款记录约束，客户端不能提交实际生效的会员布尔值或任意预算。人工收款凭证引用只保存必要标识，不把支付密钥、完整银行卡或原始敏感信息写入日志。

现有 `requireAuth` 只解析已由网关验签的身份，新写接口必须实际验签并核对写权限。部署 `verify_jwt`、函数路径和运行环境一并验收；不能把可解码 JWT 当作身份验证。数据结构与权限变更纳入下一份经批准的 migration，不修改 005 历史迁移，也不在本轮执行数据库操作。

## 7．新增验收要求

| 编号 | 必须证明的行为 |
|---|---|
| D01 | 普通用户与只读管理员不能赠送、登记收款、暂停或调预算；月会员不获得管理员身份 |
| D02 | 普通用户赠送 1 个月立即生效，试用不重复赠送；活跃会员赠送顺延且本期用量不重置 |
| D03 | 赠送 3 个月按三个账期恢复权益，月末、闰年与时区边界一致，第一期不能用三期额度 |
| D04 | 连点、网络重试、并发管理员赠送、支付回调与人工补发不会重复发放或突破预算 |
