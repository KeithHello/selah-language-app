# Selah Web 密码恢复闭环设计

> 日期：2026-10-04。状态：按已确认方案实施；本地验证与生产发布状态以 `ROADMAP.md` 为准。
>
> 后续开发入口：[开发计划](../plans/2026-10-04-password-recovery-plan.md) 。

## 目标

用户从登录窗口申请重置密码后，邮件回到 Selah 正式站点，并在该页面设置新密码。恢复链接不再只打开首页而缺少后续操作。

## 用户流程

1. 登录窗口显示「忘记密码？」入口；注册模式不显示该入口。
2. 用户填写邮箱后提交。应用校验邮箱格式，调用 Supabase Auth 发送恢复邮件，并把当前应用的站点根地址作为回调地址。成功提示不泄露该邮箱是否已注册。
3. 邮件链接回到当前站点。应用在 Supabase SDK 处理初始 URL 前识别 URL fragment 中的 `type=recovery` 和访问令牌里的邮箱提示；SDK 随后按既有默认流程从回调 URL 建立认证会话。
4. 有效会话打开覆盖层，说明正在为哪个账户设置密码。邮箱提示与会话账户不一致，或没有恢复会话时，不允许提交，并提示重新申请链接。
5. 用户输入并确认新密码。两次输入不一致、少于 6 个字符、恢复会话失效、服务端密码策略拒绝或请求限流时显示可读错误；有效请求通过 Supabase Auth 更新密码。
6. 更新成功后关闭恢复覆盖层并显示成功提示；用户也可以暂不修改并返回应用。

## 界面与语言

恢复表单覆盖现有 Web 页面，不新增独立路由或页面壳。表单在窄屏可滚动，使用现有 Selah 对话框、颜色、字体和间距规范。登录入口、表单标题、账户说明、两个密码字段、操作按钮和错误提示覆盖繁体中文、简体中文与日语。

## 边界与安全

- 回调地址来自当前站点的 scheme、host、port 与 path，不附带旧 query 或 fragment；生产可返回正式域名，本地开发继续返回本机地址。
- 访问令牌只交给 Supabase SDK 处理，不写入学习资料、日志或数据库。解析 JWT 只用于展示邮箱提示，不将其作为授权依据。
- 是否允许改密由 Supabase Auth 回调会话决定；本地状态仅用于显示恢复界面。
- 忘记密码成功文案保持邮箱枚举安全。过期、已使用或账户不匹配的链接不能更新密码。
- 不新增依赖，不改数据库 schema、Edge Functions、Supabase／Cloudflare 配置、密钥或 CI。

## 验收条件

- 登录模式可申请恢复邮件；注册模式不显示忘记密码入口。
- 登录／注册回调仍指向当前站点根地址，不带 query 或 fragment。
- 有效恢复会话展示对应账户的新密码表单；无会话或邮箱不匹配时不开放提交。
- 弱密码和确认不一致不会调用密码更新；有效输入调用 Supabase Auth，并关闭表单。
- 三种界面语言均有恢复相关文案。
- Flutter 全量测试、静态分析和 Release Web 构建通过；生产发布后核验版本、Build ID 与关键资源状态。
