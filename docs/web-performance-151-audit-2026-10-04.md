# Selah Web 1.5.1 页面加载与切换速度调研（2026-10-04）

## 结论先说

正式站 `1.5.1`（Build ID `4cdf2e39fff8020b`）相比 `1.5.0`：冷启动 Flutter 首帧从约 2.1—3.9 秒降到约 1.5—1.7 秒，热重载从约 1.1—2.2 秒降到约 0.6 秒；普通指针切页的最大帧间隔从 115—224ms 降到 24—64ms，长任务从最多 208ms 降到最多 53ms。预缓存已确认不含 `.gif` 副本（线上清单 128 项、精灵 PNG 50 个）。

未完成项：切页采样基于固定坐标点击 Flutter 画布，本机截图核验未能最终确认每次点击都命中导航；精灵首载仍有约 18.7MB（阶段一十个动作），字节总量未下降，只是顺序改为可见姿态优先。

## 方法

- 目标：https://selah-language-app.pages.dev/ ，桌面视口 1280x800，Chrome headless（channel: chrome），本机网络与 CPU 不限速。
- 探针：页面注入 `requestAnimationFrame` 间隔记录与 `PerformanceObserver(longtask)`；启动用加载遮罩 `hidden` 作为 Flutter 首帧时刻。
- 切页：完成引导后按左栏固定坐标依次点击聆聽、筆記、練習、設定、今天，每步清零探针后采样 1.2 秒。
- 样本量：冷启动 2 次、热重载 1 次、切页序列 1 轮 7 步。样本少，只作方向判断。

## 资源与预缓存核验

- 线上 `selah-precache.json`：128 项，精灵 PNG 50 个，`.gif` 0 个——约 26MB 重复副本已从线上包移除。
- 冷启动仍会下载阶段一全部十个动作（约 18.7MB）。「可见姿态优先、其余顺序补齐」改善的是时序（不阻塞首帧与首次操作），不是字节总量；后续若要降字节，需做格式评估（WebP 等）。

## 已知边界与未决项

1. 切页坐标点击未经最终视觉确认（本轮截图核验流程中断），聆听步骤的长任务信号与真实切页一致，其余步骤按保守口径视为「待视觉复认」。
2. 无障碍树只读到 2 个带标签节点；左栏导航项未读到可见 aria-label，是否缺失语义标签待专项确认。
3. 未测真实手机、未限速网络；INP／真实用户分布未采集。
4. 引导页语义节点大多无独立标签，自动化走引导只能按坐标操作，说明语义标注覆盖面偏窄。

## 建议下一步

1. 用带视觉确认的脚本复跑一轮切页（每步截图比对页面标题），坐实「无长任务」结论。
2. 精灵格式评估（动画/静态 WebP 或复用姿态的原生微动效）作为下一轮字节优化主项。
3. 补导航语义标签（左栏五项），既利于无障碍也利于自动化验收。
